# Open policy decisions (brief §11) and their defaults

Each item is a default the loop builds against. Anything marked **configurable** must be a session setting, not a hard-coded rule. The organizer can change any default before or after a phase runs.

| # | Topic | Default | Status |
| --- | --- | --- | --- |
| D1 | Declined turn | Player goes to the **back of the queue**: eligibility time resets to the moment they declined, as if they had just finished a game. Configurable: back of queue / keep spot, skip once / drop N places. | Confirmed by organizer 2026-10-21 |
| D2 | Queue tie-break | Equal eligibility time → earlier session check-in wins → then fewer games played this session → then stable player id. | Default, unconfirmed |
| D3 | New arrival mid-session | Eligibility time = check-in time. Joins behind everyone already waiting. | Default, unconfirmed |
| D4 | Resting / unavailable | Unavailable players keep their original eligibility time while away and resume it on return (no penalty for a short rest). | Default, unconfirmed |
| D5 | After a game | All participants become eligible at the game's end time, winners and losers alike (no "winners stay on"). | Default, unconfirmed |
| D6 | Skill balancing window | When on, balancing may only choose among the oldest-waiting `players_needed + 2` eligible players, and must include the single oldest-waiting player. | Default, unconfirmed |
| D7 | Partner rotation | Among valid team splits of the chosen players, prefer the split with the fewest repeat partnerships this session. Never changes *who* plays, only how they're paired. | Default, unconfirmed |
| D8 | Rules edition | The current USA Pickleball Official Rulebook at the start of phase 2. The test-author records the exact edition and the rule numbers used in `docs/RULES.md`. | To be recorded in phase 2 |
| D9 | Leaderboard threshold | Ranked only with ≥ 3 completed games (session) or ≥ 10 (historical); others shown unranked. Order: win % → wins → point differential → shown as tie. | Default, unconfirmed |
| D10 | Backup format | Single `.pbbackup` file = SQLite database copy + JSON manifest (schema version, app version, created_at, SHA-256 of the DB). Restore = **replace** after validation and explicit confirmation; current data is auto-backed-up first. No merge in v1. | Default, unconfirmed |
| D11 | Export columns | Sessions, games (one row per game with players, teams, score, court, times, status), player stats (session + historical). | Default, unconfirmed |
| D12 | Supported OS versions | Windows 10 22H2+, Windows 11; macOS 13 Ventura+ (Intel and Apple silicon). | Default, unconfirmed |
| D13 | Code signing | Unsigned builds for v1 (internal use); signing is a release-time task outside the loop. | Default, unconfirmed |
| D14 | Fairness mode | Session setting `fairness`: **balanced_games** (fewest games first: games played + catch-up credit, then longest wait, then a seeded draw that changes every round; partner rotation always on, preferring fewest repeat partners, then fewest repeat opponents, then skill balance) or **wait_time** (D2). A late arrival's catch-up credit = the fewest effective games among players already checked in (and not away) at the moment they check in. Resting keeps D4. With skill balancing on, the D6 window only swaps players on the same game count. Engine default (`DEFAULT_ROTATION_SETTINGS`) stays wait_time so D1-D7 hold; **sessions created from the app start with balanced_games + partner rotation**, and Court operations -> Game settings -> Who plays next switches it. Added after the organizer saw the earliest check-in get the most games (11 players, 2 courts). | Requested by organizer 2026-10-21 |
| D15 | Single-court sessions | The organizer asked for 1-court sessions (small groups). Kept as an **explicit opt-in** so the brief's 2-4 contract and its locked tests stay intact: `createSession(db, { …, courtCount: 1, allowSingleCourt: true })` and `setCourtCount(db, id, 1, { allowSingleCourt: true })`; without the flag 1 court is still a ValidationError. The app's court selectors offer 1-4 and send the flag only for 1 ("1 court (small group)"). Every team-up style has a 1-court rule (see D16). | Requested by organizer 2026-10-22 |
| D16 | Team-up styles | Optional rotation setting `teamUp` (absent = follows `fairness`, so `DEFAULT_ROTATION_SETTINGS` and D1-D14 are unchanged): **balanced** (D14), **longest_wait** (D2), **random**, **paddle_stack**, **river**, **fixed_partners** (+ `fixedPairs`). In the four grouping styles who plays is the balanced-games queue (fewest games, then longest wait, then the rotating draw); all free courts are filled together from the front of that queue and the style only groups those players into courts and teams. Random: the sit-out wheel is the first sort key (nobody plays again before every checked-in available player has played this cycle; late arrivals join as not yet played; extras needed to fill the last game of a cycle count toward the next one); teams come from a seeded shuffle per session and round that avoids last-game partners. Paddle stacking: players off a finished game are winners/losers; players with no result yet, or who sat out (a game started without them after their game ended, up to the latest game end), are neutral and fill in after the losers; courts in order take winners, then losers, then neutral; within a court each result is split across the teams (winners face winners) and last-game partners are split; 1 court: winners split up and each partners a loser. River: Court 1 is the top of the ladder of available courts; winners target one court up (top winners stay), losers one down, neutral players enter at the bottom; on a tie in games and wait, winners stay ahead of losers and bottom-court losers go to the waiting line first; partners split; 1 court: winners stay on when level on games, partners split, losers rotate out first. Fixed partners (doubles): a pair whose players are both waiting is one unit, as due as its later member; each court takes the unit combination with the lowest busiest-player game count, then fewest total games, then earliest places; a pair is split for one game only when keeping it together would leave out someone with fewer games (typically the only unpaired player), and the explanation says so; a player whose partner is away, playing or declined plays unpaired that turn; in singles pairs do not apply. Declines (D1), resting, unavailable or occupied courts, open courts, overrides and the rotation log work the same in every style; `assigned` events record `teamUp`. | Requested by organizer 2026-10-22 |
| D17 | Advanced team-up styles | Six more optional `teamUp` styles (settings fields `pools`, `challenge`, `roundRobin` are optional, so `DEFAULT_ROTATION_SETTINGS` and D1-D16 are unchanged). Who plays is the balanced-games queue (D14) unless stated. **mixed** (doubles): the front of the queue plays; if those players cannot make every team one man + one woman, a player at the cut may swap with one of the next two waiting players on the *same* game count (never someone with fewer games; the passed-over player is `bypassed` and stays at the front); courts take two men and two women while they last, players without a gender are flexible, leftover same-gender players team up and the explanation says so ("Not enough women … (5 men, 3 women)"); singles: opponents rotate. **pools**: pool = the player's roster pool (source `manual`) else skill vs `cutoffA` (default 3.5) / optional `cutoffB` (three pools); neither set = pool B. Courts: `auto` (largest-remainder split by pool size, at least one court per pool, pool A on top; alternate when courts < pools, so 1 court alternates), `alternate` (the pool whose next player is most due), or one pool per court. Fewest games first *within* the pool; a short pool's court stays open with a reason (default `whenShort: stay_open`) or borrows the most-due players of other pools (`borrow`). Games are level within a pool, not across pools. **round_robin**: a stored schedule generated for the checked-in, available players and available courts (games per round = min(courts, players/4)); default rounds = one cycle (ceil(pairs / partnerships per round), 1-40). Each round the players with the fewest scheduled games play (byes rotate: most games sit, then fewer byes, then a seeded draw), paired to minimise repeat partners (squared counts, local swap improvement), then repeat opponents; singles with everyone on court uses the circle method (perfect round robin). Free courts take the current round's unstarted games in order; a free court waits while the round is still in progress (rounds stay together); a missing scheduled player is replaced by the most-due waiting player not in that round; a round that cannot be fielded and has nothing in progress is skipped. Progress = `assigned` events carrying `schedule {scheduleId, round, game}` (cancelled games excluded). Late arrivals are not in the schedule (they only fill in) and the app asks to regenerate; regenerating starts at round 1. No schedule or finished schedule: Balanced, explained. Bounded exception: who plays follows the schedule. **mentor**: the front of the queue plays; ranked by skill (unrated = median of rated players present), top half partners bottom half strongest-with-weakest preferring new partnerships, teams with similar sums face each other; singles high vs low. **challenge**: on the challenge court(s) (`courts: first` default, or `all`) the team that won the last game there stays on as holders while (wins in a row - 1) < `cap` (1-3, default 2), then sits out that turn (plays only if a court would otherwise stay open); a holder resting/playing/declined breaks the team; challengers and other courts come from the front of the queue. Bounded exception: holders exceed fewest-games-first by at most `cap` games in a row (tests: spread <= cap + 1). **swiss**: the front of the queue plays, sorted by session record (win %, then point difference from tagged scores, then wins); neighbours share a court, adjacent courts swap a player when that lowers rematches; within a court fewest rematches, then repeat partners, then even teams; singles meet the next unplayed player in the standings. Every style: 1 court works, declines/resting/unavailable or occupied courts/overrides/log as D16, `assigned` events record `teamUp`. Choosing a style opens an explanation window (one typed source, `src/renderer/teamUpOptions.ts` `TEAM_UP_GUIDE`, shared by the selectors, hints and this guide). | Requested by organizer 2026-10-22 |
| D18 | Player profile fields | Optional **gender** (male / female / not set) and **pool** (A / B / C / not set) per player, plus the existing skill level (validated 1-8 when set from the app). Stored in the `settings` table as validated JSON under `player_profile:<playerId>` (malformed values read as not set; an empty profile removes the row) instead of new columns, so `SCHEMA_VERSION` stays 1 and the locked schema, migration and backup schema-version tests are untouched; backups carry profiles automatically. Editable when adding a player (skill, gender), in the roster's Edit row (skill, gender, pool) and in Player details (everyone at once). The data layer passes them to the engine as `QueuePlayer.gender` / `pool`. | Requested by organizer 2026-10-22 |
